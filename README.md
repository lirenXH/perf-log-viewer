# 性能计数器日志查看器

适用于 Ubuntu 22.04 和 Python 3.10+。仅使用 Python 标准库，无需 pip、Node.js 或联网下载依赖。

## 独立桌面 GUI（服务器 / ETX）

GUI 直接显示在服务器桌面或 ETX 远程桌面中，读取服务器上的文件，无需浏览器、HTTP 服务或 SSH 隧道。
运行时不监听任何端口，也不需要网络连接。

Ubuntu 22.04 如未安装 Tkinter，先安装一次：

```bash
sudo apt install python3-tk
```

如果公司服务器不能联网，可以由管理员通过内部软件源或离线包安装；已有 Tkinter 时不需要安装或下载。

在 **ETX 桌面中的终端**启动：

```bash
cd perf-log-viewer
python3 perf_viewer_gui.py
```

启动后点击“打开当前日志”，左侧选模块，右侧输入关键字；所有查看操作都在窗口中完成。
也可以直接加载服务器日志：

```bash
python3 perf_viewer_gui.py /path/to/perf.log
```

支持模块名称搜索、组合关键字和短语搜索、层级路径、行号范围、分页、双击查看原始行，以及导出全部匹配结果。
日志读取、查询和导出在后台执行。零值和每轮重复条目保留，导出会拒绝覆盖当前原日志。

GUI 需要同时复制 **`perf_viewer_gui.py`、`perf_viewer.py`、`perf_compare.py` 和 `perf_runs.py`**，放在同一目录。
原来的单文件浏览器版本仍可单独使用 `perf_viewer.py`。
如果出现 `no display name` 或 `couldn't connect to display`，请从 ETX 图形会话的终端启动，不要手动指定不属于该会话的 DISPLAY。

### SPEC 运行结果文件夹

单文件模式和文件夹模式同时保留。单文件模式可直接打开 `.perf`、`.log` 等文件，也可打开两份文件进行计数器对比。
文件夹模式适用于以下结构：

```text
运行结果根目录/
├── perlbench_diffmail/
│   ├── 180/
│   │   ├── 180_20261011_035534_499423.perf
│   │   ├── _180_0.010044.log
│   │   └── _180_0.010044_gzip_check.log
│   └── 10015/
│       ├── 10015_20261011_062011_2281844.perf
│       └── _10015_0.153974.log
└── gcc_g23/
    └── 1240/
        ├── 1240_20261011_062011.perf
        └── _1240_0.057653.log
```

1. 在“当前运行目录”粘贴路径并点击“加载目录”，或点击“选择目录”。选择的是包含各个子项的根目录。
2. 在“SPEC 子项”和“checkpoint”下拉框中选择结果。checkpoint 按数字大小排序。
3. 下方计数器表读取 `.perf`；上方指标表读取主 `.log` 中的 IPC、cycle、instrcount，也显示识别出的 Guest cycle spent 和 Host time spent。
4. 在“基准运行目录”加载另一份运行结果。工具按 **子项名 + checkpoint 目录名** 精确配对，不依赖 `.perf` 文件名中的时间戳或主日志文件名中的权重。
5. 指标表和计数器表均显示当前值、基准值、差值及变化百分比。两边所有 checkpoint 均可选择；只存在于一边的项保留为新增/缺失，缺少 `.perf` 或主 `.log` 会显示提示，不会自动当作数值零。
6. “移除基准”返回当前文件夹浏览；“打开当前日志/基准日志”切回单文件模式，模块搜索、关键字、分页及计数器 CSV 导出仍可使用。

同一个 checkpoint 有多份 `.perf` 或主 `.log` 时，文件下拉框允许明确选择；默认选文件名排序最后的 `.perf` 和排序最前的主 `.log`，并提示确认。
默认选择仅按文件名排序，不推断两份文件是否属于同一次运行。`*_gzip_check.log` 被排除，`.txt` 等辅助文件不会参与分析。
扫描阶段只建立目录/文件列表，选择 checkpoint 后才在后台解析对应的日志。

支持截图中的 XiangShan 汇总格式：

```text
Core 0: EXCEEDING CYCLE/INSTR LIMIT at pc = 0x453b8
total guest instructions = 40,000,001
instrCnt = 40,000,001, cycleCnt = 15,881,339, IPC = 2.518679
Seed=0 Guest cycle spent: 15,881,341
Host time spent: 12,670,505ms
```

也支持 `instrcount`、`instr_count`、`cycle`、`cycle_count` 等常见写法，以及 ANSI 颜色、千分位、小数和科学计数法。
主日志指标取每个 core 的最后一次对应输出，不累加多次汇总；多 core 分开显示。双击指标可查看两边的来源文件、行号和原文。
如果没有显式 IPC，但有有效的 instrcount 和正数 cycle，会显示两者相除的 IPC，并在来源中标明是计算值。无法识别的指标显示“未识别”。
`cycleCnt` 与 `Guest cycle spent` 分别显示；主日志里的 IPC 可能包含预热，不会自动改成 `.perf` 清零后的统计区间。
计数器导出会保护两边选中的 `.perf` 和主 `.log`，避免覆盖源文件；CSV 导出范围为当前所选 checkpoint 的计数器。

启动时也可以直接传入文件夹：

```bash
python3 perf_viewer_gui.py /path/to/spec-result
```

仓库中的 `sample_runs/current` 与 `sample_runs/baseline` 是合成示例，可以演示配对及两边缺少 checkpoint 的情况。

### 全部 checkpoint 的 IPC 对比

加载“当前运行目录”和“基准运行目录”后，点击 **“全部 checkpoint 的 IPC 对比…”**。
独立窗口会在后台提取两个目录下所有 checkpoint 的主 `.log`，不需要逐个选择 checkpoint，也不读取 `.perf`。
即使没有 `.perf`，只要目录中有主日志，也可以查看 IPC 对比。

- 每行显示子项、checkpoint、日志配对、core、基准 IPC、当前 IPC、差值、变化百分比、方向和备注。
- 可筛选上升、下降、不变、新增、缺失或无法比较，并按子项、checkpoint、日志名等搜索。点击列头排序，再次点击反向排序；数值列按数值排序，无法比较的数值排在末尾。
- 顶部显示全部结果的上升/下降等条数，以及当前筛选后的数量。
- 双击查看两边来源文件、IPC 的行号和原文，以及对应 instrcount、cycle。指令数不同会在备注提示。
- “导出筛选结果 CSV”导出所有当前筛选后的行及源文件路径，保护两边所有参与批量对比的主日志，避免覆盖。
- “重新提取 IPC”会重新扫描这两个目录，包含新生成的 checkpoint 和日志；该窗口固定使用打开时的两个目录和日志编码。

配对首先按 **子项名 + checkpoint 目录名**。如果两边各至多一份主日志，直接配对，不要求文件名或时间戳相同。
如果同一个 checkpoint 任意一边有多份主日志，则保留全部日志并按文件名精确配对，未匹配的文件标记新增/缺失，不推断哪两次运行对应。
每份主日志取各 core 最后一次 IPC，多 core 分开比较；`*_gzip_check.log` 不参与。
没有显式 IPC 时沿用单点视图的 instrcount/cycle 计算，并在备注注明来源。
缺少主日志、没有识别出 IPC、读取失败等情况都会保留，不会当成 IPC 为零；读取失败或已有日志没有可配对 IPC 时标记“无法比较”。

变化百分比 = (当前 IPC − 基准 IPC) / |基准 IPC| × 100%；基准为零时不计算百分比。
这里逐项比较原主日志的 IPC，不计算整套 SPEC 的均值或 SimPoint 加权结果，也不改变原日志的预热统计口径。

### 基准日志对比

1. 点击“打开当前日志”，加载调参后的日志。
2. 点击“打开基准日志”，加载调参前的日志。
3. 表格显示基准值、当前值、差值、变化百分比和上升/下降方向。左侧模块包含两份日志的所有模块。
4. 用“变化筛选”查看上升、下降、不变、新增、缺失或无法比较的条目。
5. “导出对比 CSV”会导出全部匹配项及两份原文；“移除基准”恢复普通日志查看。

匹配键是 **模块名 + 完整层级路径 + 计数器名称**，大小写精确匹配，不同 bank 或实例不混合。
默认“逐次配对”：同一匹配键的第 1 次、第 2 次等输出分别配对，不求和；数量不一致时额外条目标记新增或缺失。
“最后一次”只使用每份日志中每个匹配键的最后一次输出，适合查看最终 dump。

- 差值 = 当前值 − 基准值。
- 变化百分比 = 差值 / |基准值| × 100%，保留两位小数；基准为零时显示“基准为0”，不计算百分比。
- 两个百分比数值的差值以“百分点”显示，例如 10% → 12.5%，差值为 +2.5 个百分点，相对变化 +25%。
- 非数值保留原文，标记“非数值”；一个带 %、另一个不带时标记“单位不同”。
- 颜色只区分上升/下降，不判断性能好坏。
- 行号范围仍针对当前日志，设置范围后仅存在于基准的条目会被排除。
- 双击可同时查看当前和基准的原始行。对比导出会拒绝覆盖任一源日志。

工具比较原始计数，不自动按指令数归一化；比较性能时应使用相同工作负载和测量长度。
可打开 `sample.log` 和 `sample_baseline.log` 体验对比功能。

## 浏览器版启动

```bash
cd perf-log-viewer
python3 perf_viewer.py
```

浏览器通常会自动打开；也可以手动访问 http://127.0.0.1:8765 。点击“打开日志文件”选择日志。

启动时直接加载日志：

```bash
python3 perf_viewer.py /path/to/perf.log
```

体验自带示例：

```bash
python3 perf_viewer.py sample.log
```

端口冲突时使用 `--port 8766`，或 `--port 0` 自动分配端口。`--no-browser` 不自动打开浏览器。
按 Ctrl+C 停止服务。原日志不修改，临时 SQLite 索引在程序退出时清理。

## 在其他服务器上使用

只需要复制 `perf_viewer.py`；网页界面已包含在脚本中。服务器需要 Python 3.10 或更高版本。

在服务器上启动并加载服务器端日志：

```bash
python3 perf_viewer.py /path/to/perf.log --no-browser
```

在本机建立 SSH 隧道：

```bash
ssh -N -L 8765:127.0.0.1:8765 user@server
```

然后在本机浏览器打开 http://127.0.0.1:8765 。服务仅监听服务器的本机回环地址。
网页“打开日志文件”选择的是浏览器所在机器的文件；服务器已有的日志可以用启动参数加载。

## 筛选与导出

- 左侧按 `[L2 SMS Prefetcher Monitor]` 等模块标签筛选，也支持搜索模块名称。
- 顶部关键字搜索覆盖模块、路径、计数器名称、值和原文，不区分大小写。
- 多个空格分隔的关键词按 AND 匹配，例如 `prefetch accepted`。
- 双引号表示连续短语，例如 `"Useful prefetch"`。
- “层级路径包含”能进一步区分同名模块所在的不同 bank 或实例。
- 原始行号范围可隔离预热段、某一轮 dump；边界行号包含在结果中。
- 导出 CSV 或原始日志行，导出的是所有匹配项，不只是当前页。
- 同名计数器的多次输出分别保留，不求和、不覆盖，零值也保留。
- UTF-8 是默认编码；旧 GBK 日志选择 GB18030 后重新打开。

## 日志格式

```text
[PERF] TOP.SapphireCore.core.l2CacheWrapper.l2Cache.l2PfMonitor: [L2 SMS Prefetcher Monitor] Useful prefetch, 0
```

解析成模块 `L2 SMS Prefetcher Monitor`、名称 `Useful prefetch`、数值 `0`、层级路径和原始行号。
支持 `[PERF ]` 空格、ANSI 终端颜色、CRLF、负数、小数、科学计数法、十六进制及千分位数值。
未带模块标签的 PERF 行归入“未标注模块”；未识别数值的 PERF 行仍然保留，值列留空。
其他日志行不展示，但计入原始行号。该工具不判断计数器的统计口径，也不自动计算 MPKI。

文件在本机 Python 服务中分块解析，使用 SQLite 存储索引，页面分页显示，无需把所有记录渲染到浏览器。
全日志关键字搜索需要扫描记录，超大文件的首次导入和搜索可能需要等待。

## 验证

```bash
python3 -m unittest -v
```

在可用的桌面会话中启用实际 Tk GUI 集成测试：

```bash
PERF_VIEWER_GUI_TEST=1 python3 -m unittest -v
```

GUI 测试会验证目录切换、同名配对、缺失项、多文件选择、单文件兼容及源日志保护，并禁止 GUI 使用网络 socket。
